# Starshine 0.3.0 — changes from 0.2.2

This minor release brings optimizer correctness repairs, lower analysis costs,
new diagnostic tools, and stronger binary and validation contracts. It includes
78 commits after the source checkpoint for Mooncakes 0.2.2, plus the 0.3.0
release preparation. The comparison starts at
[`0f9460d3200e1ed679b4f8405368cc707a518959`](https://github.com/jtenner/starshine-mb/commit/0f9460d3200e1ed679b4f8405368cc707a518959).
The published 0.2.2 source ZIP was checked against that commit: all 2,157
archive members match. No historical tag is assumed.

The source comparison covers 1,436 files before release preparation. Many are
regression fixtures and generated coverage. The total change count is not a
count of new features or independent optimizer transformations.

## Main changes

- Repair 32 defects found in the October 17 optimization-pass audit.
- Preserve effects, traps, reference identity, local writes, and control-flow
  targets across more optimizer transformations.
- Reduce repeated work in DAE, DAE2, HOT analysis, lowering, and binary size checks.
- Add explicit application export roots to MoonBit unused-module cleanup.
- Add static-marker and paired-size diagnostics for optimization investigations.
- Require fresh final execution evidence before a reducer publishes a semantic
  failure artifact.
- Expand generated tests for typed control, reference ownership, tuple aliases,
  heap updates, GC instructions, and pass interactions.
- Regenerate the Node API and FFI from the current public source interfaces.

## Installation and compatibility

The release targets the Mooncakes module `jtenner/starshine@0.3.0` and the npm
package `starshine@0.3.0`. npm uses the `latest` tag after publication.

The previous npm release was 0.2.0. The 0.2.2 baseline in this changelog is the
Mooncakes source release. npm users therefore also receive the tested MoonBit
README revisions and source changes between those registry versions.

The npm package remains ESM. It requires Node.js 25 or later with WasmGC and
JS String Builtins. It provides the root import plus `binary`, `cli`, `cmd`,
`lib`, `validate`, `wast`, `wat`, and `passes`. These are the existing nine
public entry points. The package includes the WasmGC API and the WASI CLI.
Ordinary consumers do not need MoonBit, Bun, a native compiler, or an optimizer.

MoonBit HOT option and context interfaces now include private fields. Use their
constructor methods, including `HotPipelineOptions::new` and
`HotPassContext::new`, when constructing those values.

The portable component interface keeps its independent 0.1.1 version. The
product version change does not rename its WIT exports.

The unrelated historical npm 0.1.0 CommonJS object/factory API remains available
by exact version. That old API is not restored by this release.

## Optimizer correctness: constants and types

### Floating-point bit identity

Duplicate-function elimination now compares floating constants by their bits.
Functions that return positive and negative zero must remain distinct when a
caller can reinterpret the result. The shared comparison walks blocks, loops,
conditionals, legacy exception regions, and try-table bodies.

Raw identical-if folding uses the same bit-aware comparison. Equal numeric
comparisons must not erase a signed-zero difference between arms. Focused tests
cover both f32 and f64.

### SIMD constants and LocalCSE

The unsigned SIMD narrow fold interprets source lanes with the signed input
semantics required by the instruction. Negative i32 lanes narrow to zero;
positive values above the unsigned 16-bit range saturate at 65535.

LocalCSE assigns i32 results to `i64x2.all_true` and `i64x2.bitmask`. Lane
extraction retains its i64 result type. This prevents a reused result from
introducing an invalid local type.

Touched-function LocalCSE receives the module validation environment. Memory64
expressions keep their correct address and result types during cleanup.

### Exact and abstract references

LocalSubtyping preserves exactness when it normalizes `ref.null` types.
A nullable exact reference must not silently become an inexact reference.

DAE2 recognizes shared abstract function references in tables. It also protects
signatures exposed through imported or exported abstract-funcref globals.
Externally reachable function references constrain private signature changes.

MakeSharedObjects leaves mixed function-reference and external-reference type
domains unchanged when lowering both could merge distinct structural types.
The new fixture demonstrates the observable distinction with a type test.

## Optimizer correctness: control flow and effects

### Nontermination and unreachable code

DAE preserves a nonterminating loop before `unreachable`. Erasing that loop
would change whether execution reaches the trap.

HeapStoreOptimization preserves a looping constructor operand when it can
branch back to its owner. A read-only-looking operand can still diverge.

CodePushing checks every suffix root before moving code after an initial
`unreachable`. A call in an unreachable suffix must not become executable.

### Branch conditions, exits, and labels

RemoveUnusedBrs checks the operand of `ref.is_null` before it speculates the
condition. A call under that test can have effects or trap.

RemoveUnusedBrs counts continuation handler targets when it computes label
uses. A label used by a continuation handler cannot be discarded as unused.

SimplifyLocals keeps a write when a `br_if` condition reads that local. Branch
exit cleanup must preserve the value used to decide whether to branch.

SimplifyGlobalsOptimizing accepts its guarded scalar-read pattern only when
the `br_if` targets the local guard. A nonlocal branch is a different contract.

Vacuum keeps blocks whose earlier branches can bypass a terminal return,
unreachable, or outer branch. The final instruction alone does not prove that
all paths terminate. A separate fixture covers an earlier self-branch in a
child block before a branch table.

Precompute preserves labels referenced by continuation handlers when it
refinalizes an exact-cast block. It uses the shared complete label-use analysis.

Constant-if folding preserves branches that target the removed if's own label.
Selecting an arm does not permit stale branch depths.

### Local state, tuple values, and SSA

TupleOptimization keeps payload `local.tee` writes. Replacing a tee with its
source get would discard an observable local update.

SSA-no-merge keeps loop-carried local reads and consumes planned local-get
decisions in legacy try bodies and catch arms before following roots.

DAE's artifact-specific temporary remap requires a definite temporary write
before a read. A conditional write alone is not sufficient evidence.

HOT redundant-store elimination starts locals with WebAssembly default values.
That state is distinct from an unknown value or an uninitialized analysis slot.
The regression fixtures now test floating bit identity independently of those
default local values.

### Exception regions and tail calls

CoalesceLocals keeps functions with externally targeted try-table catches on
the guarded route. Catch exits must participate in local interference reasoning.

Dead-code elimination treats a branch to the try-table owner as a fallthrough
path where required. Tail-call-terminated blocks receive valid void shapes.

Inlining preserves legacy try locals during cleanup. It rejects a tail-call
operand hoist that would create an uninitialized non-defaultable local.

Resume rewriting traverses exception regions. Raw OptimizeInstructions marks
legacy try instructions as nested control so the shared walker visits them.

DAE2 preserves typed-if entry operands and their effects. Both the region rewrite
and its cleanup must retain the original evaluation order.

## Module cleanup and reference ownership

Unused-module cleanup preserves active element segment slots. A retained slot
can need another payload scan after function liveness becomes stronger.
Closed-world scans promote late `ref.func` references through that liveness path.

GlobalStructInference follows externally reachable references through struct
fields and array elements. It carries the external-origin restriction into
nested aggregate types and reconciles facts for equivalent struct types.
It must not replace a field value from one nominal allocation family with an
unrelated global value.

Type pruning retains all instruction type references. This includes references
that are not exposed through the most common call or local forms.
The documentation states backing-array liveness and ownership rules explicitly.

Heap2Local scopes array bailouts to unsafe locals. One unsupported use no longer
blocks unrelated safe local candidates without evidence.

GlobalTypeOptimization preserves ordered aggregate atomic stores. Shared-memory
effects do not become ordinary removable stores.

HeapStoreOptimization reports mutations that occur before a later fold is
rejected. The dispatcher and follow-up analyses must see the actual changed state.

Similar-function merging rejects size-growing candidates. Positive tests require
profitable work rather than accepting an unchanged module as success.

## New and updated public interfaces

The MoonBit binary package adds
`encoded_type_compaction_is_strictly_smaller`. It provides the type-only size
proof used before the more expensive complete-body encoding fallback.
The generated Node binary namespace exposes
`encodedTypeCompactionIsStrictlySmaller`.

The validator adds `validate_module_name_section`. The generated Node validator
namespace exposes `validateModuleNameSection`.

MoonBit unused-module cleanup adds `rume_run_host_roots_module_pass`. Callers can
supply explicit retained export names under an application host contract.
This lets an application remove exports it knows are unused. It does not change
the default assumption that public exports are observable.

Generated profiles add tuple alias-capture and Heap2Local owner-update cases.
The corresponding enum and API snapshots are updated.

The FFI is regenerated from current signatures. Integer spellings in generated
MoonBit adapters reflect the qualified compiler. Public JavaScript numeric
values retain their existing boundary representation.

## Performance and allocation work

### DAE analysis reuse

The DAE family reuses existing analysis facts and body-exposure scans instead
of rebuilding equivalent information. It transfers cleanup local counts into
capture compaction and freezes final DAE2 signature decisions before emission.

Plans are allocated when needed. DAE2 avoids throw-fold setup when the module
has no defined local tags that can use that work. These changes reduce setup
cost while retaining the existing safety checks.

### HOT analysis and lowering

HOT analysis and lowering reduce repeated reads, temporary arrays, and unchanged
copies. Private lowering arrays are created after a change requires them.
Live type groups are collected in one root scan. SSA indexes nested result-if
parents once instead of repeatedly searching them.

The source keeps the native lower-stack initialization needed for the documented
MoonBit debug compiler issue. The performance changes do not remove that fix.

### Encoded size checks

Type-only compaction proof runs before complete-body encoding where possible.
The full encoder and validation fallback remain available if the cheaper proof
cannot establish a win.

OptimizeInstructions combines local-fact collection and performs small integer
tee-reuse cleanup before HOT lifting. It also simplifies supported unsigned
sign-bit power-of-two arithmetic.

### Measurement limits

Historical October 17 native campaigns measured large-case wall reductions
between 2.3% and 7.5% for the further DAE round. All 1,366 retained residual
outputs in that comparison matched the before CLI bytes. These figures apply
to the documented inputs, source identities, controls, and environment.
They are not a universal release speed claim.

Separate allocator observations show lower traffic in selected paths. They do
not establish a general process RSS or total-heap reduction. The known GC
canonicalization and wrapper peak-memory work remains open.

A function-ordering experiment was withdrawn after benchmark regressions.
A later arm-map experiment was also rejected. Neither is presented as a shipped
performance improvement.

## Optimization diagnostics and fuzzing

### Static markers

`bun fuzz static-markers` compares two explicit bounded pass sequences on an
instrumented module. It records marker survivors, primary candidates, reverse
differences, input hashes, tool hashes, and retained outputs.

Markers can reveal code that one configuration leaves behind. They are opaque
calls and can change optimization decisions. A candidate therefore needs an
uninstrumented replay and an independent semantic explanation before it becomes
a production transform. Unsupported exception, continuation, and metadata forms
remain explicit limits.

### Paired size diagnostics

Paired optimization-size reporting records candidates from two configurations.
It separates measured size differences from a proof that one output is correct
or preferable. Source-backed transform contracts and runtime observations remain
necessary for accepted differences.

### Generated interaction coverage

The bounded GC-and-memory interaction profile combines relevant effects within
one generated module. New profiles also exercise tuple aliases, owner updates,
typed control, and optimizer boundaries that simpler cases can miss.

The fuzz harness keeps feature support, observed execution, validation, and
canonical structural comparison as separate results. A validating module alone
does not establish semantic equivalence.

### Reduction safety and deadlines

External reduction must make real byte progress and pass fresh final execution
checks before a semantic reduced artifact is published. In-process reduction
also repeats its final observation and requires the retained fingerprint.
Stale, missing, or changing observations leave the original artifact as evidence.

Reducer CLI options expose bounded predicate and subprocess deadlines through
`--predicate-timeout-seconds` and `--subprocess-timeout-seconds`. Slow external
witnesses can be bounded without silently removing execution proof.

The effect/trap scanner decodes GC-prefixed instructions and their immediates.
A type or field index byte must not be interpreted as an unrelated opcode or
false unreachable hazard.

## Packaging and source documentation

Component generation now migrates wit-bindgen's JSON package manifests to the
current Moon format before it returns or builds. It writes `component/moon.mod`
and uses the current CLI package selector. The runtime-import converter keeps
flat named parameters and results printed by newer wasm-tools. The failing
fixtures pass after these changes. WIT exports retain interface version 0.1.1.

Product metadata, generated CLI identity, FFI root dependency, and component
root dependency are synchronized for 0.3.0. The root script workspace remains
private and is not a registry package.

The npm prepack route builds from source. It compiles the WasmGC adapter, a fresh
native bootstrap optimizer, and the WASI CLI; then it self-optimizes the package

## Known limits and follow-up work

- Binaryen 133 remains the comparison target for new evidence. Historical
  v131/v132 runs retain their original identities and do not sign current code.
- Canonical shape and size gaps remain in some pass profiles. Validation and
  smaller output alone do not prove a Starshine win.
- Several proposal features are blocked by independent validator or execution
  support. Such cases remain blocked evidence rather than semantic matches.
- The broad MakeSharedObjects audit diagnostic did not complete all 10,000
  comparisons. Its observed external-tool failures reproduced on the baseline.
- The GC peak-memory blocker remains open. No general leak or RSS guarantee is
  added by this release.
- Ordinary RUME host-visible function-name policy remains open. The explicit
  application-root contract does not settle every ordinary cleanup observation.
- The documented large-artifact and Wago runtime follow-ups remain open.
- Manifest UInt64 seed precision requires further work. Exact retained manifests
  and lossless sidecars remain necessary for the affected historical campaigns.
- Browser, CommonJS, and JSPI support are not added. Existing unsupported ABI
  mappings remain explicit and guarded.
- New release validation results must be read separately from the historical
  campaign evidence below.
